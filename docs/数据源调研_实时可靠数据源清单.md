## 一、项目已接入的数据源（当日实测）

### 1.1 高德开放平台（实测✅）
- **实测结果**：用项目 `.env` 的 key 调 `place/text`，"拙政园"精确返回名称/地址（东北街178号）/经纬度/类型（国家级景点），status=1、count=100。
- **免费配额**：个人认证 15 万次/月；企业认证最高 300 万次/月（自认证起 1 年免费），超量约 24–30 元/万次。
- **注意**：个人认证仅限非商业用途；压测时注意 QPS 与日配额（个人约 2000 次/日级别，搜索类仅 5000 次/月），演示够用、上线需企业认证。

### 1.2 飞猪AI 开放平台（已接，MCP 协议）
- 提供：景点榜单、门票信息、预订链接、语义搜索——与本项目 `fliggy_ai` provider 对接（`FLIGGY_AI_API_KEY` 已配置）。
- 正式商用走飞猪开放平台（open.alitrip.com），需入驻资质（项目已预留 `TAOBAO_APP_KEY/SECRET`）。

### 1.3 和风天气（已接）
- 实时天气+逐日预报，`QWEATHER_API_KEY` + 专属 API Host 已配置。

### 1.4 携程（项目预留 `ctrip_wendao`）
- 携程问道 API（AI 旅行助手）、携程商旅开发者平台（openapi.ctripbiz.com）、玩乐开放平台（ttdstp.ctrip.com，门票供应商向）。
- 接入属商务合作范畴，建议二期。

## 二、政务开放数据平台（真实性最强，RAG 语料首选）

全国 337 个城市中 219 个已上线公共数据开放平台，一般设"文化旅游"类目，可筛选 A 级景区名录、门票、开放时间等数据集，多数支持 API 调用：

| 平台 | 地址 | 特点 |
|---|---|---|
| 北京市公共数据开放平台 | data.beijing.gov.cn | 下载+API 开发服务 |
| 浙江·数据开放 | data.zjzwfw.gov.cn | 全国领先，支持接口调用 |
| 深圳市数据开放平台 | opendata.sz.gov.cn | 28.5 亿条数据、3418 个接口 |
| 杭州市数据开放平台 | data.hangzhou.gov.cn | 下载+查询+接口 |
| 武汉市数据开放平台 | data.wuhan.gov.cn | 数据目录+接口+开发者工具 |
| 南京市政务数据开放平台 | opendata.nanjing.gov.cn | — |

**用法**：按目标城市筛选"文化旅游"数据集 → 定时同步脚本 → 清洗后双路分发（结构化事实表 + RAG 语料入库）。这是版权最干净、真实性最强的起点。

## 三、动态实时数据

### 3.1 天气（实测✅ Open-Meteo）
- **Open-Meteo**：非商用完全免费、无需 key、每天 1 万次；整合 30+ 气象模型；数据 CC BY 4.0。实测苏州当前温度 29.7°C（13:45 本地时间）。
- **商用注意**：商业用途需购买订阅（customer-api.open-meteo.com）。建议作为和风的**灾备双源**：和风超限/故障时自动切换。

### 3.2 景区实时客流（P2，商务合作）
- **百度地图慧眼**：人口地理大数据接口服务（HTTPS API）——当日累计客流、区域网格客流分布（热力图）、客源画像、性别年龄消费偏好；另有 MapV Pro 文旅大屏成品方案。
- **腾讯位置服务文旅**（lbs.qq.com/culture-tourism）：游客实时到访/区县天级监测、热力地图、游客量监控报警，可作为替代/比价。
- 两者均需商务开通账号，成本最高但无替代品；C 端问答中"现在人多吗"类问题的唯一数据来源。

### 3.3 法定节假日（实测✅）
- **timor 节假日 API**：免费，返回节假日/补班/调休。实测 2026-10-01 → 国庆节（rest=3），2026-09-05 → 周六。**注意：默认程序 UA 会被 403，需带浏览器 UA**，可靠性中等。
- 权威兜底：国务院办公厅每年发布的节假日安排（官方文件，人工录入结构化表，一年一更）。

## 四、交通数据的合规红线（重要）

- **12306 官方明确：从未授权任何第三方平台发售火车票，也没有公开的余票查询 API**（央广网报道）。12306 网页端提供免登录余票查询，但仅限人工。
- 市面上的"12306 API"（如聚合数据）与社区抓取方案（含各类 MCP Server）**数据真实性和稳定性无保障，商用有合规风险，不建议接入**。
- **项目建议口径**：火车票时刻/余票类问题 → 引导用户至 12306 官方渠道查询（与现有 `test_no_demo_content.py` 的"不造假数据"原则一致）；机票/酒店 → 飞猪开放平台（需资质）或携程商务合作。

## 五、RAG 知识语料分级（入库 `/api/semantic/add`）

| 层级 | 来源 | 用途 | 处理 |
|---|---|---|---|
| 1 | 政务开放平台、景区官网/公众号公告、文旅局官网 | 事实+政策类语料 | 清洗校对后入库，标 `source_level=official` |
| 2 | 景区官方解说词/导览词、地方志、博物馆文物档案 | 文化讲解核心语料 | 需授权，POI 级切块 |
| 3 | 百科类（维基/百度百科等） | 补充覆盖 | 人工校对后使用 |
| 4 | UGC（马蜂窝/小红书/抖音） | 体验视角补充 | 降权 + 事实断言不采信 + 入库前消毒 |

更新机制：定时增量 + `effective_date` 过期降权（与《文旅RAG方案》一致）。

## 六、落地到本项目的路径

1. **新增 provider**：在 `api_registry.py` 的 `API_PROVIDERS` 加条目 + `.env.example` 加密钥变量（如 `OPEN_METEO` 无 key，可直接内置）。
2. **数据分流**：票价/客流/天气 → 工具调用；政策 FAQ/景点文化 → RAG 入库。当前 RAG 写入口只有手动 `/api/semantic/add`，建议加"政务数据集同步脚本 → 清洗 → 批量入库"管道。
3. **缓存 TTL 建议**：天气 10 分钟、客流 5 分钟、节假日每日、景区政策 T+1。
4. **灾备**：天气双源（和风主 + Open-Meteo 备），超配额自动降级。
