# 行程规划 RAG 信息清单（通道分流口径）

> 定位：说明"文旅行程规划"需要哪些信息、各自走哪条通道（RAG 向量库 / API 实时通道 / 用户上下文）、当前落地状态。
> 铁律回顾：**"选哪个、怎么玩、什么政策"进 RAG；"现在几点能进、还剩几张票、今天下不下雨"走 API；"这家几口人偏好什么"来自用户上下文。**

## 一、按规划环节的信息分流表

| 规划环节 | 需要的信息 | 通道 | 现状 |
|---|---|---|---|
| ① 选景点：哪些值得去、适合谁 | 景点档案（主题标签）、精华看点、适合人群、避坑经验 | **RAG** | ✅ 部分已入库 |
| ② 排日程：第几天去哪、待多久 | 游玩时长、最佳时段、开放时间**规律**、是否需预约+提前几天、地理聚类 | RAG（规律）+ 高德 API（坐标） | ✅ 大半已有 |
| ③ 连起来：动线与耗时 | 景区间交通方式与耗时、地铁覆盖、接驳 | 高德路径 API + RAG（交通规律） | API ✅；交通知识 RAG ❌ |
| ④ 大交通：怎么到这个城市 | 购票渠道说明、退改签政策 FAQ、车站/机场到市区方式 | RAG FAQ；时刻余票→引导 12306/OTA | ❌ 全缺（只做政策，不做余票） |
| ⑤ 住宿：住哪、什么档次 | 商圈推荐、酒店/民宿类型与价位段描述 | RAG（知识）；房态房价→OTA API（需资质） | ❌ 缺 |
| ⑥ 餐饮：吃什么、在哪吃 | 本地菜系、必吃清单、美食街区、餐馆 POI | RAG（知识）+ 高德餐饮 API | 🔄 餐饮 POI 已入库 |
| ⑦ 预算估算：够不够、怎么分 | 各项价格水平、门票档位、餐饮人均 | 结构化库+API；价格政策→RAG | ✅ 部分已有 |
| ⑧ 当天校验：今天适合吗 | 实时天气+预报、客流、临时闭园、票务余量 | API（和风+Open-Meteo ✅、飞猪AI ✅、慧眼需商务） | ✅ 天气双源已接 |
| ⑨ 写行程书：讲解与贴士 | 景点文化讲解、贴士、季节建议 | **RAG** | ✅ 部分已有 |
| ⑩ 个性化：这一家怎么玩 | 用户画像、多轮上下文、历史行程 | 用户上下文（非 RAG） | ✅ travel_context_service |

## 二、RAG 向量库采购清单（6 类，按补齐优先级）

| # | 类别 | 内容粒度 | 状态 |
|---|---|---|---|
| 1 | 景点知识（核心，以 POI 为单位） | 档案+主题标签、游玩时长/路线/看点、预约规则、开放时间规律、适合人群 | 🔄 样本已入库，按城市补全 |
| 2 | 政策 FAQ（一问一块） | 免票优待、退改签规则、实名制与证件、禁带物品 | 🔄 官方政策页已入库 |
| 3 | 交通知识 | 城际到达概览、市内交通规律、车站/机场到景区接驳经验 | ❌ |
| 4 | 住宿知识 | 住宿区域推荐（按行程主题）、类型与价位段 | ❌ |
| 5 | 餐饮知识 | 本地菜系、必吃清单、美食街区、老字号 | 🔄 餐饮 POI 已入库，深度介绍缺 |
| 6 | 攻略与行程模板 | UGC 游记（降权、不采信事实）、"2 日亲子路线"模板 | ❌ |

## 三、通道口径（易混淆点）

- **开放时间"规律"（周一闭馆、旺季时段）→ RAG**；**"今天实际开不开"→ API/官方公告校验**。
- **门票价格政策（谁半价、依据文件）→ RAG**；**实时票价与余量 → API**。
- **退改签规则文本 → RAG FAQ**；**具体订单的改签操作 → 引导官方渠道**。
- **UGC 游记 → RAG 但降权**，元数据 `source_level=ugc`，事实类断言不采信。
- 扫描版 PDF 需 OCR（当前管道会提示跳过）；政府 JS 渲染页建议下载后走 `--file`。

## 四、语料摄取工具

- 结构化数据行（POI/政务数据集）：`backend/scripts/sync_rag_corpus.py`（amap/file/url 三源）
- 文档（PDF/DOCX/HTML/TXT/MD）：`backend/scripts/ingest_documents.py`（file/dir/url）
- 检索验证：两脚本均支持 `--verify "查询"`；语料分布看 `document_chunks` 按 `job_id` 分组。
