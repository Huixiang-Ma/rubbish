# 对话式行程规划 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 把首页“规划我的旅程”改成逐步对话式引导，支持用户自由插话并把想法融入规划，生成过程以流式对话呈现，最终行程书以弹窗展示。

**架构：** 前端以单页聊天编排器接管输入流程：把原始表单拆成一组顺序问题和补充输入，用户的自然语言会被合并进当前草稿并用于提交到现有 `/api/plans`。结果区不再直接承载主内容，而是在生成完成后触发行程书弹窗；原有结果面板保留为摘要锚点或入口。后端尽量复用现有计划生成与轮询接口，只补一个最小的对话/流式输出适配层，避免重写整条规划管线。

**技术栈：** FastAPI、原生 HTML/CSS/JS、现有 `/api/plans` 与 `/api/plans/{job_id}` 轮询接口、现有 `ExperienceService` / `dialogue` 机制、浏览器原生 `EventSource` 或 `fetch` 流式读取（若后端输出 SSE）。

- [ ] **步骤 3：把 `createPlan()` 改成先走对话草稿，再落到现有 payload**

将原来直接读取表单值并提交的逻辑拆成两个阶段：
1. 从对话草稿中读取当前已确认信息。
2. 把自然语言补充合并到 `payload`，再沿用现有 `fetch(${apiBase}/api/plans, ...)`。

最小伪代码：

```js
const draft = buildPlanDraftFromDialogue();
const payload = buildPlanPayload(draft);
await submitPlan(payload);
```

注意保留现有的 `bumpMemory()`、`showStrip()`、`pollStatus()`、`loadResult()` 调用链，不要破坏后端状态流。

- [ ] **步骤 4：验证页面上旧表单不再是主入口**

运行页面后确认：顶部主区首先看到的是逐步引导式对话，而不是一组并排输入框；原字段可以作为后台草稿存在，但不再作为第一视觉层呈现。

### 任务 2：实现流式对话输出与用户插话

**文件：**
- 修改：`frontend/index.html:1738-1812`
- 修改：`frontend/index.html:2223-2250`
- 修改：`backend/app/api/experience.py:19-129`（仅在必须时补流式能力）
- 修改：`backend/app/services/experience_service.py:189-225`（仅在必须时补更适合规划对话的回复结构）

- [ ] **步骤 1：写一个失败用例，锁定“消息应逐字出现”**

在浏览器里先观察：当前的对话回复是一次性写入的，没有打字机/流式表现。目标是让系统消息逐段出现，用户能在回复过程中继续补充新想法。

- [ ] **步骤 2：实现一个前端流式渲染器**

优先使用前端动画模拟流式输出；如果后端已有 SSE/分段返回，再改成真正流式读取。实现一个 `appendStreamingBubble(text)` 或 `streamReply(...)`，逐块更新同一个气泡内容。

建议的 UI 状态：
- 用户发送后，先插入“思考中…”气泡。
- 系统回复分段追加。
- 用户若继续补充，新的补充插入到当前对话末尾，并触发下一轮规划合并。

参考伪代码：

```js
async function streamAssistantReply(source) {
  const bubble = createBubble("assistant", "正在整理你的想法…");
  for await (const chunk of source) {
    bubble.textContent += chunk;
  }
}
```

- [ ] **步骤 3：让用户自由插话并影响下一轮规划**

为对话草稿加一个 `context` 对象，保存：
- 目的地、天数、预算、人数等结构化字段
- 用户自然语言想法列表
- 已确认/待确认字段

在用户追加想法时，把它写进 `context.userNotes`，并在下一次生成请求前合并到 `payload` 或提示词里。

- [ ] **步骤 4：如果后端需要支持真正的流式输出，就补一个最小 SSE 适配**

只在现有接口不够用时改 `backend/app/api/experience.py`：新增一个生成规划回复的流式接口，复用 `ExperienceService` 的事实抽取和回复生成逻辑，输出 SSE 文本事件。不要动现有计划生成主链路。

- [ ] **步骤 5：验证流式体验**

打开页面，发送一句补充说明，确认回复不是整段瞬间出现，而是分段出现；再补一句，确认新输入会进入下一轮规划上下文。
