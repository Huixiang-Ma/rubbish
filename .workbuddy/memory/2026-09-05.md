## 文旅 RAG 数据源方案咨询
- 用户为 AI 旅行规划项目（WL项目）征集文旅数据源，要求实时性、真实性、可靠性，用于 RAG 检索。
- 给出的核心结论：**双路架构**——静态/慢数据（POI、景区介绍、攻略文化背景）清洗后入向量库走 RAG；实时数据（票价余量、客流、天气、营业状态）不入库，通过 API + Tool Call 实时拉取。
- 推荐数据源分层：L1 权威静态（高德/腾讯地图开放平台 POI、文旅部 A 级景区名录与全国旅游监管服务平台）；L2 实时动态（和风/彩云天气、12306 余票、航旅纵横/飞常准航班、景区官方预约小程序、地方公共数据开放网如济宁 5A 景区实时客流 API）；L3 内容知识（马蜂窝/携程结构化内容、维基/百度百科，UGC 需多源交叉验证+时效过滤）；L4 时效事件（文旅局公众号、官方活动日历）。
- 治理要点：chunk 元数据带 source/发布时间/抓取时间/置信度；TTL 策略（价格营业状态 24h 重抓）；权威优先级 官方 > 平台结构化 > UGC。
- 合规红线：爬虫遵守 robots 与个保法/数据安全法；地图展示需 GCJ-02 与审图号；OTA 数据商用需商务授权（携程联盟/美团开放平台）。
- 提示了 WorkBuddy 可用连接器：途牛旅行（tuniu-travel）、腾讯地图（tencent-map），当前未连接。
