## 架构变更：单管线 → toC/toB 双管线（推翻 08-31 的结论）

08-31 记录的"只有 1 条 Agent 管线、toB 端没有独立 Agent"**已失效**。9/1 新增两个 toB Agent 与管线分叉机制：

- `backend/app/services/plan_processor.py` 的 `PlanProcessor.pipelines` 变为 dict，含 `"toc"` / `"tob"` 两条列表。
  - toC：Researcher → Planner → Itinerary → Validator → **Debate → Mood**
  - toB：Researcher → Planner → Itinerary → Validator → **Consultant → Compliance**
  - 共享底层 4 个节点，尾段按方向分叉。
- `backend/app/services/pipelines.py`（新增）负责方向判定：`resolve_pipeline()` 看 `user_input` 是否带 `customer` 或 `tenant` 字段，有则 toB。旧 state 无 `pipeline` 字段时按此规则重新判定，兼容历史任务。
- 新增 `backend/app/agents/consultant.py`（顾问话术 + 分项报价 + 回访建议，不调 LLM）与 `compliance.py`（租户校验摘要 + 风险清单 + 数据口径声明 + 审批建议，不调 LLM）。两者都只读 Validator 的结构化输出。
- **尾段并行**：`TAIL_PARALLEL_NAMES = {"Debate","Mood","Consultant","Compliance"}`，`_run_tail()` 在全部未完成时用 ThreadPoolExecutor 并行跑；断点恢复且部分完成时退回顺序补跑。Mood 仍受 `user_input.mood` 非空限制。
- 目前 8 个 Agent + 1 个 Reporter 汇总节点。**仍只有 Debate/Mood 调 LLM**，Consultant/Compliance 是确定性模板。

## 重要约束：不要改代码里的 agent.name

中文名仅用于**文档与讲解**，未落代码。原因（改动会炸）：

1. `agent.name` 直接当作产物文件名 `agent_outputs/<name>.json`，并写进 `state.json` 的 `completed_nodes` / `resume_from` / `agent_outputs` —— `data/jobs` 下已有 7000+ 文件，历史任务会全部失效。
2. 白标交付依赖"原稿 sha256 校验行"，改名会破坏 sha256 对应关系。
3. 硬编码散落多处：`pipelines.py` 的 TOC/TOB_PIPELINE 列表、`plan_processor.py` 的 `TAIL_PARALLEL_NAMES` 与 `agent.name == "Validator"/"Mood"` 判断、frontend 展示层。

若用户坚持要代码里出现中文，安全方案是只加 `display_name` 字段（展示用），`name` 保持英文不变。
