00一页纸结论

🔴结论一：Multi-Agent 已经从卖点降级为入场券

飞猪「帮帮」、携程商旅「程星途」（7 个 Agent）、美团 CatPaw（3 万+ Agent）全部是多智能体架构。 再拿"我们用了多 Agent"当差异化，在答辩和路演上已经不成立。

✅结论二：本方真正站得住的只剩三条

说得清（决策过程可追溯、可辩论、可审计）／中立 + 可私有化（不绑供应链、不抽佣）／工程韧性（进程级断点续跑）。 这三条目前全赛道无人正面做。

⚠️结论三：最危险的是「算得准」——它现在是未兑现的承诺

已知缺陷：北京 3 天 5000 元预算实测产出 5714 元（必然超支，根因在 travel_context_service.recommend_hotel() 未按人数放大交通成本、未预留门票与市内交通）。 而携程商旅敢承诺"AI 审批准确率 99.95%，出错由平台兜底赔付"。 在修掉这个 bug 之前，"算得准"不能对外讲。

定位建议（修正版）

版本表述
原定位给游客一份"算得准、说得清、可验证、走得通"的行程
建议改为给游客一份「每一步都能解释为什么」的行程；给企业一套「不绑供应链、可私有化、可审计」的 AI 生产闭环

为什么改：「走得通」「算得准」需要真实供应链与实时库存，本方 MVP 没有，讲了会被追问击穿； 「说得清」是本方唯一有代码实证、且全赛道空白的能力。

📌一条硬纪律

厂商宣称的效率提升数字（"效率提升 10 倍""可用率提升 70%"）全部标注为【官方宣称】，不得当作客观事实引用。 这类数字普遍缺少对照组定义、样本量与统计口径，作为趋势参考可用，作为论据不可用。

2.3 三个结构性判断

①竞争维度已从"供应链能力"转向"决策效率 + 信任机制"

网经社分析师观点：OTA 的 AI 既是机会也是陷阱——"如果 AI 推荐不能真正做到更懂用户，它可能只是一个昂贵的智能客服"。 算法透明度正在成为新的信任基础。

②通用 AI 正在截流 OTA 的入口，且开始明码标价

用户以前打开携程是搜索比价下单，现在打开豆包问"五一去哪玩"然后直接跳转预订——OTA 从"决策起点"退向"履约环节"。

③信源偏好是结构性的，中立性无法被平台型 AI 提供

QuestMobile 五一旅游 AI 信源研究（2026-04）：豆包旅游问答中信源引用携程 82.6%、通义千问 75.9%、DeepSeek 64.0%； 豆包推荐类问题中抖音内容矩阵被引用 96.9%、攻略类 98.5%。

每个 AI 都把自己生态的内容当主信源，这件事不会因品牌方努力而改变。 → 这直接证明：一个"不绑任何供应链的中立规划器"有独立存在的空间。这是本方 toB 路线最硬的一块地基。

05逐家深度剖析

每家按统一三段式组织：是什么 → 在赛道里的角色 → 对本方的启示（可借鉴 / 可规避 / 可切入）。 完整 21 列数据见配套 Excel。

5.1 飞猪·帮帮（原「问一问」）—— toC 体验天花板

是什么：2025-04-17 上线的「问一问」是业内首个 Multi-Agent 架构旅行 AI；2026-08-10 在杭州升级为「飞猪帮帮」， CEO 庄卓然用三个 E 定义战略：AI for Experience / Ecosystem / Enterprise。

角色：最强的一点是AI 长在交易链路的每个环节，而不是缩在聊天框里——智能面板直接落在 App 首页下方， 能力同时嵌入搜索栏、行程页、订单页，以及机票/酒店/民宿/度假每个细分频道。搜机票时说"不要过境签、中转别隔夜"→ 直接在结果里筛； 酒店列表里说"想要一间能看到东方明珠夜景的"→ 从全量供给里找出真正符合的房间。App 首页三大入口「帮我想/帮我订/帮我办」。

官方数据【官方宣称】：结果可用率较上一代提升超 70%，可比任务平均耗时减少近 10%；3 个月核心开发周期上线 148 个复杂需求， AI 生成代码占比超 85%；2026 春节 AI 订单量环比 +800%、门票单量 +24 倍、AI 咨询量占比超 60%。

✅对本方的启示
  • 可切入 · 中立性：飞猪不可能做不抽佣的中立推荐，推荐偏向返佣伙伴是结构性的，不是努力问题。
  • 可切入 · toB 私有化：飞猪的 B 端是"商家工具"（AI 发品/优化/营销/服务四大智能体），不是"企业自己的行程生产与治理平台"。
  • ⚠️ 必须区分：飞猪的「弱网断点续传」是移动端网络层序号化续接；本方是服务端 kill -9 进程级续传 + CheckpointStore（state.json + sha256）。两者不是一回事，答辩时若被追问必须讲清层级差异。
  • 📌 可借鉴：把 AI 能力嵌进具体业务环节（而非单独聊天入口）这一产品思路。

5.2 携程商旅·程星途 —— 本方 toB 端最重量级正面竞品 ★

是什么：2026-04-23 携程商旅首届全球商旅伙伴大会发布「携程商旅 AI 生态」全景图及《2025-2026 商旅管理市场白皮书》。 包含 4 大场景、7 个 AI Agent：差旅问答、行程预订、差旅审批、差旅洞察、合规风控（程信）、财务结算、资源采购， 外加能力共享场景的 MCP 共享平台。

🔥最重要的一个设计：AI + 责任兜底

"虽然 AI 可以帮企业管理者做决策，但决策背后的责任，AI 却无法替企业承担。这也是为什么很多同类产品使用率不高的原因—— 审批人不敢把审批权完全交给 AI，怕出了问题自己担责。"

携程商旅的做法：差旅审批 Agent 风险检测准确率超 99.95%；如果因为智能审批出错造成订单损失，将由携程商旅来兜底。【官方】

技术底座【官方宣称】：携程集团 30 年酒旅经验 + 携程商旅 20 年差旅管理实践；直连四大 GDS、Travelfusion、NDC； 整合欧铁/日铁/网约车/接送机/租车；100 万+ 企业客户、6000 万出行人实战数据；2921 项技术专利；每日 100TB 数据。

开放生态：MCP 共享平台——企业可将携程商旅的 AI 能力接入自有系统（OA/ERP），员工在自己系统中直接调用差旅问答与行程预订 Agent。 已接入 15+ 家企业，成立「商旅 AI 蜂行联盟」。

💡一个可以直接用的答辩话术

问："携程商旅都敢承诺出错赔付了，你凭什么让人信你？"

答："赔付是事后补偿，我们要做的是事前可追责。赔付解决'钱谁出'，审计留痕解决'责谁负、下次怎么改'。 在文旅局、国企这类对合规审计要求高于成本补偿的客户那里，后者才是刚需。而且我们不卖库存，推荐不掺返佣—— 这是我们敢把每个 Agent 的决策过程全量摊开的前提，也是平台型玩家结构性地做不到的事。"

5.3 同程·程心 AI —— 编辑体验最好，增量重规划的正面参照

是什么：同程旅行自研旅游专属大模型，行业内首个完成深度合成算法备案和生成式大模型备案的 OTA（双重备案）。 2025-03-07 完成与 DeepSeek 融合，首批面向 210 万用户开放测试。国际版 DeepTrip 2026-04 升级 2.0（17 语种）。

角色：行程可视化编辑体验全赛道最佳——拖拽增删排序 + 一键打包同程供应链下单，另有「AI 手绘行程图」社交功能。 一个有争议的选择：做独立 App「行程助手」而非嵌入主应用。

劣势：攻略分享弱；无实时交通/值机/数字人；改动后仍是整段重排逻辑。

✅ 可切入：本方的增量重规划（局部 diff，改动不破坏整段）比它更细。但要讲清楚：同程是"改完重排"， 本方是"改哪动哪 + 保留未受影响段落的成本与时空约束"。

📌 可借鉴：拖拽式编辑 + 手绘行程图的社交属性，是 toC 侧提升感知价值的高性价比功能。

⚠️ 可规避：独立 App 路线需要单独获客，本方 MVP 阶段不应复制。

5.4 携程·问道 / Trip.Planner —— 覆盖最广，但深度参差

劣势（本方最应关注的部分）：

  • AI 还停留在聊天框形态：需先点搜索栏，再进入"旅行 AI"入口，体验路径繁琐
  • 回答往往从携程榜单出发给标准路线，个性化调整能力不足
  • 澎湃新闻实测结论很直接："携程问道目前成不了 AI Agent。" 原因是大模型的发散性大于精确性，在需要精确规划和落地的任务上只能当 copilot。 实测让它出上海 10 月 2~6 日行程，只规划到 10 月 4 日，剩下两天让用户自己发挥

✅ 可切入："规划不完整 / 规划不落地"是头部产品的公开弱点， 而"完整性 + 可行性校验"恰是本方 11 态状态机 + 出行要素估算引擎的设计目标。

5.5 豆包 —— 入口截流者，也是"可信"叙事的最佳靶子

角色：最大的威胁不是它做行程，而是它抢走了"第一个问题"。用户以前打开携程是搜索比价下单， 现在打开豆包问"五一去哪玩"然后直接跳转预订。2026-08 豆包正式对经其入口跳转的酒店订单收取独立佣金，国内首个 AI 对话入口明码收费案例。

劣势：无旅游产业数据、无实时库存、无交易闭环、无结构化编辑；旅行规划"瞎编能看不能走"，空间感缺失、黑盒不信任被诟病。

✅ 可切入：其"空间感缺失 + 黑盒不信任"正是本方时空约束 + 辩论可解释的靶子。 ⚠️ 不要拼通用问答，那是必输的战场。 📌 新观察：豆包开始对跳转订单收佣金，说明"AI 入口"已是可定价资产；本方若能证明推荐"更可信"， toB 侧的商业逻辑（中立、不抽佣、可议价服务费）反而更清晰。

5.6 小红书·点点 —— 真实性壁垒最高，本方消费陷阱图谱的天花板

角色：内容真实度全赛道最高，避坑经验强。它解决的是"AI 瞎编"这个信任问题的另一半—— 不是让 AI 更会推理，而是让 AI 引用真人写的东西。攻略模式读取平台笔记（媒体称"啃 10 亿篇笔记"），接入 DeepSeek-R1。

⚠️ 这是本方最需要诚实的一条：本方的"消费陷阱图谱"若只靠种子数据， 拼不过小红书的真 UGC。必须接真实点评/笔记 API 才成立。在接之前，这个功能应当降级为"演示能力"并明确标注。 📌 可借鉴：引用溯源的产品形态——把每条建议挂到真实来源上。本方已有 agent_outputs 留痕， 可进一步做成"每条建议 → 来源 → 置信度"的可视化卡片。

5.7 支付宝·出行助手 —— 行中最强，行前不参与

唯一全支持值机/实时交通/打车/电子票证的产品，行中出行全链路无人能及。劣势：无结构化攻略规划、无编辑、无 UGC、无数字人。

✅ 互补而非竞争：本方聚焦行前规划，不抢其交通主场。 📌 明确划界：本方 MVP 不含行中能力，应在对外材料中主动声明，避免被追问时失分。 （注：官方产品页为 SPA 未直接抓取，功能描述来自媒体 + 应用描述，置信度中等。）

5.8 腾讯智慧文旅 / 数字人导览 —— 体验最炫，能力极偏

面向景区/博物馆/文旅局（B/G 端）：数字人导览、AR/扫码智能讲解、文博演艺推荐、智能客服。底座为混元大模型 + 数字孪生 + AR/VR。案例：AI 游云南数字人导览。

⚠️ 更正：v2 模板中的产品名「元家」未在官方资料确认，官方口径为"智慧文旅平台 / 数字人导览"，本版已更正，对外材料应停止使用该名称。

📌 注意：腾讯在 B/G 端文旅已有成熟方案，本方 toB 若面向文旅局/景区，这条赛道不是空白， 需要说清差异（本方是"行程生产 + 治理"，腾讯是"行中导览 + 营销"）。其数字人/AR 是本方标注为演示的能力，不碰或明确标注。

5.9 DeepSeek —— 推理最强，旅行最弱，但可私有化思路相近

通用推理大模型，旅行仅为场景之一。官方 API 为云端 SaaS，按 token 分时计费；开源权重可本地部署（第三方证实，官方 API 文档未提供私有化托管条款）。 北二外评测因个性化 + 多模态两项垫底。

⚠️ 注意：DeepSeek 的"可私有化"与本方 toB 思路相近，但它没有旅行专有数据。 本方的私有化价值不在"能本地跑模型"，而在"带着文旅领域知识和编排逻辑一起私有化"。

📌答辩必须区分的层级差异

飞猪的"断点续传"解决的是移动端弱网下请求断了重发（网络层、有序号即可续接）； 本方解决的是服务端进程被 kill -9 后从 CheckpointStore 恢复执行状态（进程级、需状态持久化 + 幂等 + 产物校验）。 两者不在同一层，不能混为一谈，也不应声称"我们也有断点续传所以打平"。

8.2 三条真正站得住的护城河

1
说得清 · 决策过程可追溯

实证：agent_outputs/*.json 逐节点留痕、决策辩论、翻车预演、11 态状态机可回放。

为什么对手做不到：平台型玩家的推荐逻辑与返佣策略耦合，摊开决策过程等于摊开商业利益。推荐偏向返佣伙伴是结构性的，不是 bug。

外部佐证：Expedia 调研显示仅 8% 旅客敢让 AI 代订——行业缺的不是生成能力，是信任。
2
中立 + 可私有化

实证：本方不接任何 OTA 库存，无交易抽佣。

为什么对手做不到：携程商旅的存在价值就是卖携程的库存，飞猪的价值是卖飞猪的库存。中立 = 自我否定，这在商业上不可能发生。

外部佐证：QuestMobile 显示豆包 82.6% 引携程、96.9% 引抖音内容矩阵——每家 AI 都优先引用自己生态，中立性无法从平台内部产生。
3
工程韧性 · 可验证的可靠性

实证：CheckpointStore（state.json + sha256）、kill -9 进程级恢复、Prometheus 指标 + 审计日志。

为什么对手不做：这是"不出事时没人看见"的能力，对 C 端转化率没有直接贡献，商业优先级天然靠后。

⚠️ 风险：用户无感。必须转译为 SLA 语言——"任务中断后可从中断节点继续，不重复计费、不丢中间产物"，而不是"我们有断点续跑"。

8.3 🔴 最高优先级风险：「算得准」目前是未兑现的承诺

🔴问题实证

scripts/smoke_test 第一条 happy path：「北京 3 天 5000 元 + origin 上海」实测预估 5714 元 → 进 WAITING_BUDGET_APPROVAL，等不到 COMPLETED。

根因

travel_context_service.recommend_hotel()

allowance = budget - intercity_cost - days*150

1. intercity_cost 用的是单人往返价，实际支出要 × travelers
2. allowance 只扣餐饮，没扣门票与市内交通

→ per_night_allowance 虚高 → 住宿总是顶格选「品质型 1000 元/晚」
→ 预算被吃光 → 必然超支
⚠️连带伤害

README.md 演示脚本第 1 条「北京 3 天 5000 元 → COMPLETED」实际不成立。 如果答辩现场按 README 跑，会当众翻车。

对照：携程商旅敢说"AI 审批准确率超 99.95%，出错由平台兜底赔付"。本方在预算这一项上连自洽都做不到。

处置（按优先级）

优先级动作
P0立即修：recommend_hotel 增加 travelers 参数，fixed = intercity_cost*travelers + days*150*travelers，再为门票/市内交通预留约 25% 额度后才分档。需同步改 validator.py 两处调用
P0立即改文案：README 与对外材料中暂停"算得准"表述，或改为"成本可拆解、可追溯"（这是真话）
P1把缺陷变成演示亮点：主动展示"预算超支 → 触发审批 → 人介入 → 重规划通过"，把缺陷讲成"人在回路"的价值证明
